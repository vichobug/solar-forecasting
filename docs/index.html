Case study

Forecasting large solar flares from magnetogram time series

A gradient-boosted model reaches 0.84 True Skill Statistic predicting M/X-class flares from twelve hours of SHARP magnetic-field data — ahead of a 2024 contrastive-learning benchmark, and the product of finding two data bugs before finding any model improvement.

SWAN-SF benchmark dataset PyTorch · scikit-learn Source

Large solar flares are rare, costly, and — in principle — predictable from a region's magnetic field behavior in the hours before eruption. This project trains and compares five model families on the SWAN-SF benchmark, working up from aggregated summary statistics to raw sequence models. The best result, TSS 0.839 / HSS 0.216, comes from a tuned gradient-boosted tree ensemble — not the neural networks it was compared against — and depends on one dominant feature that corroborates existing solar-physics literature rather than an artifact of the pipeline.

Data

SWAN-SF: nine years of the Sun's magnetic field

An active region is a patch of the Sun's surface where the magnetic field is intensely tangled — visible as a sunspot. When that field is sheared past a breaking point, it can snap into a simpler configuration and release a flare: a burst of X-ray radiation ranked A through X by intensity, each class roughly ten times brighter than the last. Large flares (M and X class) are rare but consequential, capable of disrupting satellites, GPS, and power grids — which is also why flare datasets are heavily imbalanced by nature, not just by sampling choice.

SWAN-SF tracks this behavior via SHARP parameters — Space-weather HMI Active Region Patches, numeric summaries computed from NASA's Solar Dynamics Observatory magnetogram images for each active region. The full benchmark spans 4,000+ active regions and 10,000+ recorded flare events across roughly nine years (May 2010–August 2018), split into five non-overlapping, time-segmented partitions so that no partition leaks information about another's time period. Of 51 available SHARP parameters, this project uses the 24 most commonly cited in the forecasting literature — total unsigned flux, current helicity, gradient sharpness around the polarity inversion line, and related measures of stored magnetic energy.

Each sample is one active region's twelve-hour history (60 timesteps at 12-minute cadence) leading up to a forecast point, labeled by whether a large flare followed. Training partitions are imputed, normalized, and then synthetically rebalanced toward 50/50 (random undersampling, Tomek-link cleaning, and TimeGAN oversampling) with C-class events excluded; test partitions receive only imputation and normalization, left at the natural rate — around 2% positive. That gap between an artificially balanced training world and a naturally rare test world turns out to matter more than any architecture choice that follows.

Approach

How the model evolved

A naive Logistic Regression and HistGradientBoosting model on hand-aggregated statistics (mean, standard deviation, min, max, and final value per parameter) established a first baseline. From there, a 1D-CNN and an LSTM were built in PyTorch to learn directly from the raw sequences instead of the aggregated view.

The first training run exhausted memory and forced a hard reboot on an 8GB machine: loading five test partitions as 64-bit floats and then casting to 32-bit briefly held both copies at once, a spike of roughly 5.4GB. The fix was structural rather than clever — stream one partition at a time, check available memory before each heavy step, and run a watchdog that terminates the process before the operating system has to.

A more consequential problem surfaced once training was stable: validation TSS reached 0.90, above even the best published result for this dataset. The cause was methodological, not architectural — the validation split was a held-out fold of the training data, which had been synthetically rebalanced with TimeGAN, so near-duplicate synthetic sequences were leaking across folds. Validating instead on an untouched, naturally-imbalanced slice of the test set brought the number down to a defensible 0.51 — and exposed a second issue: predictions collapsed to a single class for long stretches of training.

That collapse traced to a distribution mismatch: training data is resampled to roughly 1:1, while the real class ratio is close to 52:1. A loss weight applied to the already-balanced training data did nothing. Undersampling the positive class to a 10:1 ratio and applying a loss weight that matched that ratio raised CNN test TSS to 0.66.

Pairing that CNN with a newly tuned gradient-boosted ensemble was the next step. The hyperparameter search crashed three times with a segmentation fault before the cause was found — the boosting library's internal thread pool colliding with the search's own parallelism on constrained hardware — resolved by capping the thread count. On its own, the tuned ensemble reached a test TSS of 0.84, ahead of the ensemble and every network attempted, and stable within a narrow band (0.82–0.87) across every held-out partition.

Interpretation

What the model actually uses

Permutation importance on the final model, computed on the held-out validation partition, shows one feature carrying most of the signal:

  1. R_VALUE_min0.1068
  2. R_VALUE_max0.0146
  3. TOTFX_std0.0123
  4. SAVNCPP_max0.0092
  5. MEANGBZ_max0.0070
  6. TOTFY_std0.0059

R_VALUE — unsigned flux near strong-gradient polarity inversion lines — outweighs every other feature roughly sevenfold. That it dominates is not a surprise specific to this pipeline: R_VALUE is an established flare precursor in the solar-physics literature, which is a better sign than a higher score alone would have been.
